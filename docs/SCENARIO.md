# Медиаярмарка «День народного единства» — сценарий

Источник: предоставленный PDF «Сценарий Медиа-ярмарки „День народного единства“» (8 страниц). Дата мероприятия — **6 ноября 2026 года**, а не 4 ноября: 4 ноября — тема праздника и материалов станций.

## Расписание по PDF

| Время | Действие |
| --- | --- |
| 08:00–08:30 | Подготовка станций; ведущие и регистрация уже работают |
| 09:15–09:30 | Работа станций |
| 10:20–10:35 | Работа станций |
| 11:25–11:40 | Работа станций |
| 12:30–12:35 | Опрос по медиацентру внутри платформы |
| 13:25–13:40 | Работа станций |
| 14:30–14:45 | Встреча в актовом зале, объявление победителей |

Время последнего блока станций в PDF набрано как «13:25 - 13-40»; здесь нормализовано только написание времени. Автоматическое переключение флагов по часам не подразумевается: организатор управляет регистрацией, начислениями и опросом отдельно.

## Команды и прохождение

- Одна учётная запись представляет команду из **1–3 человек**. При регистрации обязательны название команды, логин, пароль, имя, фамилия и класс каждого участника.
- Состав хранится как `members` с полями `firstName`, `lastName`, `className`, возвращается в `/auth/me` и включается в административную выгрузку `/users/export.xlsx` (до трёх участников по порядку).
- Команда показывает свой QR-код волонтёру для начисления за станцию. При отсутствии телефона по PDF администратор регистрирует команду и выдаёт бумажный QR-код.
- Начисление за одну станцию однократное: повторный запрос возвращает `409`. Завершение определяется фактом начисления, **в том числе при нуле баллов**, а не положительным балансом.
- `/tasks/progress` возвращает станции с признаками `completed`, `completedAt`, `earnedPoints`.
- В интерфейсе участника отображаются только задания типа `station`. Ранее созданные задания других типов остаются в базе: скрытие не является удалением.
- Самостоятельные игровые начисления через `/quiz/submit` и `/game/snake` отключены (`410`), независимо от флага активности мероприятия.

## Семь основных станций

| № | ID при создании seed | Название | Краткое задание |
| --- | --- | --- | --- |
| 1 | `scenario_station_1` | Прямой эфир | Записать включение на фоне хромакея: подтверждённые факты, событие, место/время, значимость, финальная фраза |
| 2 | `scenario_station_2` | Фотоохота «Сокровища России» | Найти пять карточек с предметами разных народов России и сфотографировать с ними команду |
| 3 | `scenario_station_3` | Медиапочта | Получить открытку за подписку на каналы медиасовета и школы; подписать и передать адресату либо забрать |
| 4 | `scenario_station_4` | Фейк новости | Проверить карточку новости; объяснить минимум два признака надёжной или сомнительной информации |
| 5 | `scenario_station_5` | Народное радио | Чётко прочитать текст с карточки за 30 секунд; материалы по возрастным уровням |
| 6 | `scenario_station_6` | Мастерская «Медиа ИИ» | Тест «Кем ты был в прошлом», фотография, обработка в Remini, передача результата на печать |
| 7 | `scenario_station_7` | Журнал Новая Эра | За 3–5 минут создать карточку для одной из пяти рубрик коллективного журнала |

«Сцена Медиасовета» и «Регистрация» — организационные блоки, не дополнительные зачётные станции. «Редакционный спецкор» на последней странице PDF — дополнительная разработка; **не включён** в семь основных станций и не создаётся seed-скриптом. Уже существующее задание с таким названием скрипт не удаляет.

### Материалы, которых пока нет

- **Карта станций ожидается от организаторов.** PDF упоминает карту, но не содержит утверждённых мест, координат и изображения карты. Seed оставляет `lat` и `lng` равными `NULL`; вымышленные координаты не используются.
- **Вопросы опроса по медиацентру в PDF не приведены.** Seed не создаёт вопросы и варианты ответа. Их должен согласовать и добавить администратор до открытия опроса.
- Для «Медиа ИИ» PDF ссылается на тест после сценария, но предоставленный документ не содержит самого теста и ответов. Это отдельные недостающие материалы станции, а не готовый платформенный опрос.
- PDF не задаёт шкалу баллов. Новые станции получают значение из **текущей настройки `station_points`**, а не новую придуманную шкалу. Нулевая действующая настройка допустима.

## Ручное наполнение базы

Файл: `server/src/seed-scenario.js`. Запускать вручную **внутри API-контейнера** с существующим окружением подключения к MySQL. Рабочая директория стандартного образа — `/app`:

```sh
node src/seed-scenario.js
```

Не подключать к автоматическому старту API или деплою. До ручного запуска убедиться, что схема уже применена, текущая настройка `station_points` корректна, а копия базы сохранена.

Поведение:

1. Одна транзакция; строка настройки `station_points` блокируется, чтобы сериализовать повторные параллельные запуски этого скрипта.
2. Настройка `survey_open` добавляется как `'0'` только через `INSERT IGNORE`. Уже существующее значение не меняется. `event_active` и `registration_open` не меняются.
3. Для каждой станции проверяются существующие **станции** по названию. При совпадении создание пропускается независимо от прежнего ID. Сравнение игнорирует регистр, кавычки, повторные пробелы, `ё/е`, варианты тире и префикс номера станции; для фотоохоты и мастерской допускается название без обозначения формата.
4. Если стабильный ID уже занят другим заданием, оно сохраняется, а создание этой станции пропускается с сообщением о конфликте. Конфликт разбирается администратором вручную.
5. Только отсутствующие станции создаются со стабильными ID `scenario_station_1` … `scenario_station_7` (каждый 18 символов, предел поля — 24).
6. **Нет удаления, обновления или перезаписи существующих заданий**, их описаний, ценности, координат и начислений. Повторный запуск не «исправляет» старые станции и не обновляет их баллы после изменения настройки.
7. При отсутствующем или некорректном `station_points` выполнение завершается ошибкой без подстановки произвольного значения. Допустимо целое неотрицательное число в пределах текущей API-валидации (0–10000).

Если в старых данных уже есть дубликаты станций, seed их сохраняет и не создаёт ещё одну. Фильтр участника работает по типу `station`, а не по префиксу `scenario_`: старые станции также доступны; нестанционные задания только скрыты из этого интерфейса.

## Независимое управление опросом

Флаги `/event`: `active`, `registrationOpen`, `surveyOpen`.

- `active` управляет доступностью начислений волонтёрам.
- `registrationOpen` управляет самостоятельной регистрацией.
- `surveyOpen` отдельно управляет приёмом ответов: опрос можно открыть при `active: false`.
- Закрытый опрос возвращает `409` при отправке. Открытие без подготовленных вопросов не создаёт вымышленных вопросов и не делает пустой опрос готовым.
- По расписанию опрос запланирован на 12:30–12:35; перед этим организатор должен добавить согласованные вопросы. Время само по себе не переключает флаги.

## Приватная ручная smoke-проверка

Вне git-корня, рядом с существующими приватными smoke-скриптами: `../PRIVATE-DEPLOY/smoke_scenario.py`.

Скрипт использует только стандартную библиотеку Python (`urllib`, XML/ZIP для XLSX). Адрес API и административные реквизиты читает из существующего `smoke_survey_export.py` через AST, **без исполнения** старого теста и без публикации реквизитов в репозитории.

**Не запускать на мероприятии без согласованного окна обслуживания:** тест временно меняет глобальные флаги и добавляет синтетический вопрос, который на время проверки будет виден в опросе. Не следует запускать одновременно с действиями организаторов или других тестов.

Проверяет:

- обязательный состав команды из 1–3 человек, полные поля, регистрацию и `/auth/me`;
- состав из трёх участников в XLSX и запрет выгрузки для участника;
- станционный прогресс до и после начисления **0** баллов, повторное начисление `409`;
- сохранность временного нестанционного задания при исключении его из прогресса;
- закрытый опрос `409`, открытый опрос при `active: false`, сохранение ответа;
- `410` для игры и викторины при обоих значениях `active`.

Существующие вопросы, задачи и пользователи не редактируются и не удаляются. Если в опросе уже есть вопросы, ответы на них появляются только у временного тестового пользователя и удаляются вместе с ним. В блоке `finally` удаляются только отслеженные временные вопросы, задачи и пользователи, затем восстанавливаются **все исходные значения** `active`, `registrationOpen`, `surveyOpen` — не безусловное `true`. Ошибка одной очистки не отменяет попытки остальных очисток и восстановления флагов. При сетевой ошибке, принудительном завершении процесса или отказе очистки потребуется ручная проверка: скрипт выводит оставшиеся ID и исходные флаги при ошибке восстановления.

Эти файлы подготовлены для ручного применения; создание файлов само по себе не выполняет seed, тест или деплой.
