# Медиаярмарка — сайт мероприятия

Сайт для медиаярмарки с тремя ролями и общим табло очков. Фронтенд — статический
(GitHub Pages), данные — в **MySQL** на отдельном сервере через небольшой API на Node.js.

```
GitHub Pages (https://vsnp-moscow.github.io/media-fair/)
        │  HTTPS + Bearer-токен
        ▼
Node.js API (Cloud.ru VM, Docker, 127.0.0.1:4010)
        ▼
MySQL 8.4 (Docker, том mf_db)
```

Раньше все данные лежали в `localStorage` браузера, поэтому у каждого устройства была
своя база. Теперь база общая: участник показывает QR, волонтёр начисляет баллы,
табло на проекторе сразу видит результат — с любого устройства.

## Возможности

- **Администратор** — пользователи (роли, команды, пароли) с выгрузкой в Excel, задания
  (станции, викторина, змейка), настройки начисления очков, конструктор опросника,
  запуск и остановка мероприятия, краткое табло.
- **Участник** — статичный QR-код, «Змейка», опросник (появляется, когда мероприятие идёт),
  история начислений с автообновлением; на странице входа доступна самостоятельная
  регистрация (логин, пароль, команда).
- **Волонтёр** — сканирование QR камерой (включается кнопкой) или ручной ввод кода,
  начисление баллов за задание, лента последних начислений.
- **Мероприятие** — кнопка в панели админа скрывает у участников QR и «Змейку» и закрывает
  начисления волонтёров; очки и история сохраняются.
- **Табло** — отдельный экран `dashboard.html` для проектора, автообновление раз в 5 секунд.

## Защита от накрутки

- Очки за станцию задаёт администратор в задании, волонтёр не может их «подкрутить».
- Повторное начисление за одно и то же задание запрещено (уникальный индекс `user_id + task_id`).
- Викторина начисляет очки только за улучшение лучшего результата.
- Змейка начисляет очки только за превышение личного рекорда.
- Пароли хранятся как bcrypt-хэши, авторизация — JWT, все записи проверяются на сервере.

## Структура

```
media-fair/
├── index.html          # вход + создание первого администратора
├── admin.html/.js      # панель администратора
├── participant.html/.js# кабинет участника
├── volunteer.html/.js  # кабинет волонтёра
├── dashboard.html/.js  # табло на проектор
├── config.js           # адрес API
├── api.js              # клиент API (fetch + токен)
├── app.js              # общие функции страниц
├── snake.js            # игра «Змейка»
├── qrcode.min.js       # локальная библиотека QR
├── style.css
└── server/             # API + MySQL
    ├── src/            # Express: auth, users, tasks, awards, quiz, game, settings
    ├── sql/schema.sql  # схема MySQL (идемпотентная)
    ├── compose.yml     # Docker: mysql:8.4 + api
    ├── Dockerfile
    └── .env.example
```

## Локальный запуск

```bash
cd server
cp .env.example .env        # заполнить пароли и JWT_SECRET
docker compose up -d --build
curl http://127.0.0.1:4010/api/health
```

Фронтенд: любой статический сервер из корня проекта, например

```bash
python -m http.server 8080
```

и открыть <http://localhost:8080/index.html> — `config.js` сам выберет
`http://localhost:4010/api` для localhost.

## Развёртывание

Пошаговая инструкция для Cloud.ru VM — в [docs/DEPLOY.md](docs/DEPLOY.md).

Коротко:

1. Сервер: `/opt/media-fair`, `.env` (права 600), `docker compose up -d --build`.
2. Caddy: отдельный хост `mf.<ip>.sslip.io` → `127.0.0.1:4010`.
3. GitHub Pages: закоммитить фронтенд, адрес API — в `config.js`.
4. Первый вход: открыть `index.html`, создать администратора (форма появляется, пока база пуста).
