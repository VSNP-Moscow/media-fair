# Медиаярмарка — сайт мероприятия

Сайт для медиаярмарки с тремя ролями и общим табло очков. Фронтенд — статический
(GitHub Pages), данные — в **MySQL** на отдельном сервере через небольшой API на Node.js.

```
GitHub Pages (https://vsnp-moscow.github.io/media-fair/)
        │  HTTPS + Bearer-токен
        ▼
Node.js API (Cloud.ru VM, Docker, 127.0.0.1:4010)
        ▼
MySQL 8.4 (Docker, том mf_db)
```

Раньше все данные лежали в `localStorage` браузера, поэтому у каждого устройства была
своя база. Теперь база общая: участник показывает QR, волонтёр начисляет баллы,
табло на проекторе сразу видит результат — с любого устройства.

## Сценарий 6 ноября 2026

Актуальные условия — в [docs/SCENARIO.md](docs/SCENARIO.md). Один кабинет и QR на команду из 1–3 человек; в регистрации сохраняются имена, фамилии и классы. Кабинет содержит баллы, семь этапов со статусами прохождения, место для будущей карты и независимо открываемый опрос. Игра и старая викторина отключены на сервере; исторические начисления сохранены. Администратор может печатать QR и выгружать составы команд в Excel.

## Возможности

- **Администратор** — команды и составы, печать QR, выгрузка в Excel, станции,
  настройки баллов, конструктор опросника, карта по этажам и независимые кнопки станций и опроса.
- **Команда** — статичный QR, баллы, этапы со статусами прохождения, карта станций с кнопками
  этажей, опросник по отдельной команде администратора. Самостоятельная регистрация 1–3 участников.
- **Волонтёр** — сканирование QR камерой (включается кнопкой) или ручной ввод кода,
  начисление баллов за задание, лента последних начислений.
- **Мероприятие** — остановка скрывает QR и закрывает начисления волонтёров;
  баллы и этапы сохраняются. Доступность опроса не зависит от работы станций.
- **Табло** — отдельный экран `dashboard.html` для проектора, автообновление раз в 30 секунд.

## Карта станций

Администратор загружает до 6 изображений (JPG, PNG, WebP) и распределяет их по этажам 1–3 на странице `map.html`. Фото автоматически уменьшаются в браузере перед отправкой; исходные файлы на сервере не хранятся. Участник видит кнопки только тех этажей, для которых есть изображения, и может открыть фото на весь экран. Изображения хранятся в MySQL вместе с остальными данными и попадают в резервные копии.

## Результаты опроса

Отдельная страница `survey-results.html` доступна только администратору: распределение ответов и открытые ответы команд, обновление каждые 30 секунд, выгрузка ответов в `.xlsx`. В главной панели остаётся компактный конструктор без подробной статистики. Excel содержит команду, логин, дату и отдельную колонку на каждый текущий вопрос; множественный выбор записывается названиями вариантов через точку с запятой.

## Выдача доступа

Кнопка «Новый пароль + Excel» у пользователя заменяет пароль только после подтверждения и выдаёт файл с логином и новым случайным паролем. Исходные пароли не восстанавливаются и не хранятся в открытом виде. Файл содержит действующий пароль: передавайте его только владельцу аккаунта и удаляйте ненужные копии. При сетевой ошибке после замены старый пароль уже может не работать — повторная выдача создаст ещё один новый пароль.

## Защита от накрутки

- Очки за станцию задаёт администратор в задании, волонтёр не может их «подкрутить».
- Повторное начисление за одно и то же задание запрещено (уникальный индекс `user_id + task_id`).
- Старая викторина и «Змейка» отключены: их API возвращает 410 без начисления баллов.
- Опрос отправляется один раз на команду; его закрытие проверяется на сервере.
- Пароли хранятся как bcrypt-хэши, авторизация — JWT, все записи проверяются на сервере.

## Структура

```
media-fair/
├── index.html          # вход + создание первого администратора
├── admin.html/.js      # панель администратора
├── users.html/.js      # пользователи и поиск
├── survey-results.html/.js # результаты опроса
├── map.html/.js        # карта станций по этажам
├── participant.html/.js# кабинет участника
├── volunteer.html/.js  # кабинет волонтёра
├── dashboard.html/.js  # табло на проектор
├── config.js           # адрес API
├── api.js              # клиент API (fetch + токен)
├── app.js              # общие функции страниц
├── snake.js            # игра «Змейка»
├── qrcode.min.js       # локальная библиотека QR
├── style.css
└── server/             # API + MySQL
    ├── src/            # Express: auth, users, tasks, awards, quiz, game, settings
    ├── sql/schema.sql  # схема MySQL (идемпотентная)
    ├── compose.yml     # Docker: mysql:8.4 + api
    ├── Dockerfile
    └── .env.example
```

## Локальный запуск

```bash
cd server
cp .env.example .env        # заполнить пароли и JWT_SECRET
docker compose up -d --build
curl http://127.0.0.1:4010/api/health
```

Фронтенд: любой статический сервер из корня проекта, например

```bash
python -m http.server 8080
```

и открыть <http://localhost:8080/index.html> — `config.js` сам выберет
`http://localhost:4010/api` для localhost.

## Развёртывание

Пошаговая инструкция для Cloud.ru VM — в [docs/DEPLOY.md](docs/DEPLOY.md).

Коротко:

1. Сервер: `/opt/media-fair`, `.env` (права 600), `docker compose up -d --build`.
2. Caddy: отдельный хост `mf.<ip>.sslip.io` → `127.0.0.1:4010`.
3. GitHub Pages: закоммитить фронтенд, адрес API — в `config.js`.
4. Первый вход: открыть `index.html`, создать администратора (форма появляется, пока база пуста).
